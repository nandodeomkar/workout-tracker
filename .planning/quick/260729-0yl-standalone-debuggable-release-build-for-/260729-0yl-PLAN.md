# Quick Task 260729-0yl: Standalone Debuggable Release Build

## Goal

One documented command produces and installs an APK that:

1. Runs fully **without Metro or the PC** (JS bundle embedded).
2. Does **not** show the expo-dev-client launcher screen.
3. Stays **debuggable**, so `adb shell run-as com.anonymous.workouttracker cat files/SQLite/workout.db` keeps working — the only backup path until Phase 7 (Backup & Export) ships.
4. Installs **over** the current build without uninstalling, preserving existing workout data.

## Why release-variant, not a bundled debug variant

`node_modules/expo-dev-launcher/android/build.gradle:49-67` maps the `debug` *and* `debugOptimized` source sets to the dev-launcher source set; only `release` gets `src/disableInRelease` (gated by `expo.devlauncher.configureInRelease`, which is not set in `android/gradle.properties`). A bundled debug APK would still cold-boot into the dev-client launcher hunting for a dead Metro — unusable in a gym.

The release variant excludes the dev launcher entirely and bundles JS by default (the RN Gradle plugin's `debuggableVariants` defaults to `["debug"]`, so only `debug` skips bundling). Adding `debuggable true` to it restores `run-as` without reintroducing the launcher.

Supporting facts (verified against the live repo):

- `android/app/build.gradle:115` — the release buildType already uses `signingConfig signingConfigs.debug`, i.e. the same key as the installed dev build → in-place upgrade, data preserved.
- `android/app/build.gradle:69` — `enableMinifyInReleaseBuilds` defaults to `false`, so R8/Proguard is off. Low breakage risk.
- `android/app/build.gradle:108,112` — exactly one `buildTypes {` and one `release {`, so an anchored string insert is unambiguous.

## Hard constraint: the change cannot live in `android/`

`.gitignore:41` ignores `/android` and `git ls-files android` is empty — this is a Continuous Native Generation project and `android/` is generated output. A hand-edit to `android/app/build.gradle` would be uncommittable and destroyed by the next `expo prebuild`. The change must live in tracked source: a local Expo config plugin registered in `app.json`.

## Tasks

### Task 1 — Config plugin

**Files:** `plugins/withDebuggableRelease.js` (new)

**Action:** Local Expo config plugin using `withAppBuildGradle` from `@expo/config-plugins` (already installed; exported at `build/index.d.ts:26`). Inserts `debuggable true` into the release buildType.

Requirements:
- **Opt-in only** — no-op unless `WT_DEBUGGABLE_RELEASE=1`. Default builds stay clean so this can never leak into the Phase 8 Play Store release.
- **Idempotent** — guarded by a marker comment; applying twice must not duplicate the line.
- **Fails loudly** — throws if the `buildTypes {` / `release {` anchors are missing, rather than silently emitting a non-debuggable APK the owner discovers weeks later when `run-as` fails.
- Anchors by locating `buildTypes {` then the first `release {` after it (string index scan, not a broad regex).

**Verify:** `node -e` smoke test applying the plugin's transform to the real `android/app/build.gradle` contents — asserts the line lands inside the release block, is idempotent on re-apply, and throws on malformed input.

**Done:** Plugin file exists, all three smoke assertions pass.

### Task 2 — Register plugin + document the build

**Files:** `app.json`, `docs/device-testing.md` (new)

**Action:** Add `"./plugins/withDebuggableRelease"` to `app.json`'s `plugins` array. Write `docs/device-testing.md` with the full build+install command, including the machine-specific env prerequisites (this shell has no java/adb on PATH by default): `JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"`, `ANDROID_HOME="$HOME/AppData/Local/Android/Sdk"`, both `bin` dirs prepended to PATH, plus `WT_DEBUGGABLE_RELEASE=1`. Document the `run-as` DB backup command and the Phase 8 unwind (drop the env var; the plugin then no-ops).

**Verify:** `npx expo config --type prebuild` resolves without error and lists the plugin.

**Done:** `app.json` registers the plugin; docs note committed.

### Task 3 — Build, install, verify on device

**Files:** none (verification only)

**Action:** Run prebuild + `expo run:android --variant release` against device `5dqwzpdqemsc6xpb`.

**Verify** — all four must pass:
1. **Marker applied:** generated `android/app/build.gradle` contains `debuggable true` inside the release block.
2. **Metro-off test (the decisive one):** confirm nothing is listening on port 8081 *before* launching, then cold-start the app and screenshot. A pass with Metro still running proves nothing.

Device constraints: `adb shell input tap`/`swipe` are blocked (INJECT_EVENTS, MIUI/HyperOS) and `uiautomator dump` fails — navigate via deep links (`workouttracker://`) and capture evidence with `adb exec-out screencap -p`.

**Done:** All four checks pass.

## Out of scope

Phase 7 backup/export; production keystore generation or rotation (Phase 8); any change to app TypeScript/React source, `db/` schema, or migrations.

## Owner action — not executed by this task

`android/app/debug.keystore` sits inside the gitignored `/android` tree and is backed up nowhere. If `android/` is ever regenerated with a fresh keystore, the signing key changes, in-place upgrade becomes impossible, and reinstalling **wipes the on-device SQLite database** — weeks of workout data. Copy that file somewhere outside the repo before the trial begins. Deliberately left as an owner action: where a signing key gets stored is the owner's call.
