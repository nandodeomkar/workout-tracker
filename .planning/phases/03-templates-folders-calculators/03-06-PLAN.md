## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| keypad input → inline calculators | Current-row weight/reps flow into solvePlates/estimate1RM/buildWarmupSets |
| warm-up accept → sets write | An accepted warm-up weight reaches `insertSet` (a SQLite write) |
| save-as-template → templates write | Captured working-set counts/reps reach db/templates.ts writes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-16 | Tampering | warm-up accept insertSet | mitigate | Reuses `insertSet` which runs `assertValidWeightKg`/`assertValidReps` before the write (existing T-02-04 guards); accepted weight is a plate-solved value, converted via displayToKg |
| T-03-17 | Tampering | save-as-template writes | mitigate | createTemplate/addTemplateExercise apply their guards (Plan 03); capture output is bounded (non-negative counts) by the pure fn; targetWeightKg null by construction (D-02) |
| T-03-18 | Tampering (data integrity) | template pre-fill merge | mitigate | History filtered to non-warmup before merge (Pitfall 4); row count bounded by target_sets; merge is the tested pure fn (Plan 02), not ad-hoc screen logic |
| T-03-19 | Denial of Service | inline calculator inputs | accept | Sheets clamp non-negative + rely on solvePlates fp/below-bar guards (Plan 01); no unbounded work |
</threat_model>
