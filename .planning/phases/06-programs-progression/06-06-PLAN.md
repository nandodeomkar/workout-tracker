## Phase Goal (MVP user story)

**As a** lifter, **I want to** run a structured multi-week program that advances through its days and auto-progresses my working weights, **so that** I can follow a proven plan without recalculating loads every session.

Final slice: let the user author progression rules on their own templates and assemble a custom program from them. After this plan a user isn't limited to the two bundled programs — they can build their own linear-or-%TM program from their existing templates.

<objective>
Extend `components/TemplateBuilderForm.tsx` with the per-exercise progression authoring field (D-17) writing `template_exercises.progression`, and build the custom program builder (`app/programs/new.tsx`) that assembles an ordered list of existing templates into a program (PROG-01), chaining into TM-setup when the picked days include %TM exercises (D-16).

Purpose: Deliver PROG-01's "user can create a program as an ordered list of template days" and D-17's single authoring surface — the two remaining pieces of the phase.
Output: progression authoring in the shared template builder; a working custom program builder screen.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03 | Tampering | authored increment_kg / pct / reps | mitigate | Builder steppers are bounded (increment min 0, pct 30-100%, reps via stepper >=0); the serialized progression JSON is re-validated in db/programs.ts's finish-time parser (Plan 04 T-06-01) before any math, so authored-but-out-of-range values cannot poison progression. |
| T-06-01 | Tampering | stored progression JSON shape | mitigate | Authoring writes only the two locked shapes ({type:"linear"} / {type:"percent_tm"}); no free-text rule DSL (PROG-05 stays out of scope), keeping the parser's accepted shapes small and validatable. |
| T-06-04 | Tampering | createProgram / addProgramDay writes | mitigate | Parameterized Drizzle writes via the Plan-02 data layer guards (assertValid* on name/position); screen never builds SQL. |
| T-06-SC | Supply chain | package installs | accept | No package installs this phase. |
</threat_model>
