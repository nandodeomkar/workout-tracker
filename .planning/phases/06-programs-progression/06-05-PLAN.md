## Phase Goal (MVP user story)

**As a** lifter, **I want to** run a structured multi-week program that advances through its days and auto-progresses my working weights, **so that** I can follow a proven plan without recalculating loads every session.

This slice completes the percent-of-training-max engine end-to-end: set your TMs up front (manually, from a 1RM, or from your best logged e1RM), start a wave day and see plate-loadable prescribed weights pre-filled, and get a training-max bump when you finish a full cycle. After this plan the 5/3/1-style bundled program is fully usable.

<objective>
Make the %TM engine functional: build the TM-setup sheet (D-16/D-10) with both compute-from-1RM sources, pre-fill %TM prescribed weights at day start (D-13), add the training-max bump on cycle wrap (D-12) into `applyProgressionAndAdvance`, add the Training Maxes section to program detail, and render %TM finish outcomes + the cycle-complete banner on the summary screen.

Purpose: Deliver PROG-03 — per-exercise training maxes driving computed wave weights that climb one bump per completed cycle.
Output: functional `training-maxes.tsx`, %TM prefill + TM-bump in `db/programs.ts`, Training Maxes section on detail, cycle-complete banner on finish.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-entered TM / 1RM → training_maxes write | Numeric keypad values reaching a DB write |
| best logged e1RM (records path) → TM prefill → training_maxes write | A value computed from stored history (computeExerciseRecordBoard) feeding the TM field and, on save, the DB write |
| stored TM + scheme pct → prescribed weights | Training max and percentages driving computed set weights |
| cycle-wrap detection → TM bump write | Wrap flag gating a persistent TM increase |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
