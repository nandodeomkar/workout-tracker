## Phase Goal (MVP user story)

**As a** lifter, **I want to** run a structured multi-week program that advances through its days and auto-progresses my working weights, **so that** I can follow a proven plan without recalculating loads every session.

First demoable slice: after this plan a user can open Programs from More, add the bundled Linear 5x5, see the "Next in program" card on the Workout tab, open program detail, and start any day — the started workout is tagged with its program origin. Progression on finish arrives in Plan 04; this slice delivers add + start end-to-end.

Purpose: Give programs a reachable, demoable surface (add bundled → see on home → start a day) so Plan 04's finish-flow progression has a live program to act on.
Output: five `app/programs/*` files (manager, detail, + placeholder training-maxes/new), Settings row, home card, root route registration.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02 | Tampering / DoS | dayPosition passed to startWorkoutFromProgramDay | mitigate | dayPosition sourced from the rendered program_days list (never free-typed); db layer (Plan 02) validates/bounds it; card uses the stored current_day_position. |
| T-06-06 | Tampering | Add & start reading bundle definitions | mitigate | Screens call materializeBundledProgram (clone-only) — never write back to the imported JSON module; Plan 02's clone-independence guarantee holds. |
| T-06-07 | Information disclosure / crash | starting a non-active program's day | mitigate | Non-active program day-start routes through the switch-active confirmation so a program's pointer is never silently advanced (D-05 distinction). |
| T-06-SC | Supply chain | package installs | accept | No package installs this phase. |
</threat_model>
