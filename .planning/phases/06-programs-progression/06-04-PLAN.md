## Phase Goal (MVP user story)

**As a** lifter, **I want to** run a structured multi-week program that advances through its days and auto-progresses my working weights, **so that** I can follow a proven plan without recalculating loads every session.

This slice completes the linear engine end-to-end: finishing a program day now evaluates the working sets, bumps/holds/deloads the prescribed weight, and advances the pointer — with the outcome shown on the finish screen. After this plan a user can complete a Linear 5x5 day and watch the weight climb.

<objective>
Add `applyProgressionAndAdvance` to `db/programs.ts` (the finish-time orchestration: evaluate success via `lib/progression.ts`, write the next weight + fail counter in place, advance/wrap the pointer) and wire it into `app/active-workout/summary.tsx` behind the program-origin guard, rendering the "Program progress" section (linear success/hold/deload) and the pointer-advance caption.

Purpose: This is D-02 (advance + progress on finish) made real for the linear engine — the moment the program actually does its job.
Output: `applyProgressionAndAdvance` + tests + the finish-screen Program progress UI.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored progression JSON → finish-time math | Free-text template_exercises.progression parsed and fed to resolvers |
| finished-workout set data → success evaluation | Logged sets (incl. warmups) evaluated for progression |
| current_day_position → pointer advance | Stored pointer index advanced against the program's day count |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | parsing template_exercises.progression at finish | mitigate | JSON.parse wrapped in try/catch; validate discriminant + numeric ranges (increment_kg >= 0, pct in (0,1]) before any resolver call; a bad rule is skipped, never crashes the finish (Pitfall 2/Security Domain). |
| T-06-02 | Tampering / DoS | pointer advance | mitigate | Advance strictly via nextDayPosition = (pos+1) % dayCount — never trust a stored index against a stale dayCount. |
| T-06-07 | DoS (crash) / correctness | finish-flow running on non-program workouts | mitigate | Guard on programId != null as the first check before any program query (Pitfall 1/7); ad-hoc/empty finishes do zero program work. |
| T-06-08 | Tampering | warmup sets skewing success eval | mitigate | evaluateLinearSuccess filters type==='warmup' (Pitfall 2); test includes a mixed warmup+working fixture. |
| T-06-SC | Supply chain | package installs | accept | No package installs this phase. |
</threat_model>
