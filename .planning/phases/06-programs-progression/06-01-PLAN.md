## Phase Goal (MVP user story)

**As a** lifter, **I want to** run a structured multi-week program that advances through its days and auto-progresses my working weights, **so that** I can follow a proven plan without recalculating loads every session.

This plan delivers the tested pure-math substrate the whole phase stands on: the linear success/progression/deload resolver and the percent-of-training-max weight + TM-bump math. No UI or DB yet — this is Wave 1, the fully vitest-covered foundation both engines consume.

<objective>
Create `lib/progression.ts`: the single, pure, zero-RN/zero-Drizzle source of truth for Phase 6's progression math, plus the strength-training constant defaults locked by 06-RESEARCH.md. Built TDD (RED failing tests → GREEN implementation) since every function has defined input→output pairs (design spec §Testing lists "progression logic" as a pure-function target).

Purpose: Isolate all "clever" math in one tested module so `db/programs.ts` (Plan 02) and the finish flow (Plans 04/05) are thin transactional wrappers around a proven result — the exact pattern `lib/warmupLadder.ts` / `lib/plateSolver.ts` already follow.
Output: `lib/progression.ts` + `lib/progression.test.ts`, both green under `npx vitest run lib/progression.test.ts`.
</objective>
