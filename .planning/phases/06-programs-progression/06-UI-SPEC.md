# Phase 6 — UI Design Contract

> Visual and interaction contract for the Programs & Progression phase (PROG-01..04). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** — React Native + Expo (TypeScript) project. shadcn is a web/Tailwind-only tool and does not apply. Confirmed: no `components.json`, no `tailwind.config.*`, no `postcss.config.*` anywhere in the repo. Registry safety gate: not applicable. |
| Preset | not applicable |
| Component library | none — hand-rolled RN components styled exclusively against `theme.ts` design tokens. This phase reuses shipped Phase 1–5 components verbatim wherever the shape matches: `MetricToggle` (progression-type single-select, TM range/set-scheme entry), `NumericKeypad` (TM entry, increment entry, 1RM entry), the row anatomy established by `TemplateRow`/`WorkoutRow`/`MetricRow` (leading glyph + text column + trailing chevron/action, `theme.spacing.lg` padding, hairline `theme.colors.border` divider), `FolderSectionHeader`'s collapsible-section chrome, and `TemplateBuilderForm`'s exercise-row nested-card + stepper-group pattern (reused for the new progression-authoring sub-section and the program-builder's day-row list). No new UI framework or generic component library is introduced. |
| Icon library | **Emoji glyphs**, matching the shipped precedent (`constants/muscleIcons.ts`, bare-glyph chevron `›`, `＋`, edit `✎`, delete `🗑`). This phase adds its own small icon set (see "Icon & Copy Registry" below) — one emoji per programs-manager concept, reusing the exact `📋` template glyph where a day IS a template. `@expo/vector-icons` (already a project dependency) is not needed — every icon need is covered by emoji/bare glyphs. |
| Font | System default for all UI text. This phase introduces no charts and no new font asset — Phase 4's `SpaceMono-Regular.ttf` chart-axis font is not needed here (no victory-native usage in Phase 6). |

## Spacing Scale

This project already ships and has used a 6-token scale across five phases (`theme.spacing`) — reuse it verbatim. All values are multiples of 4. No new tokens needed for this phase.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/glyph gaps, tight inline padding, text-column internal gap |
| sm | 8px | Compact element spacing (progression-type pill gaps, set-scheme row internal gaps) |
| md | 12px | Default element spacing (row internal gaps, stepper-group gaps — matches `TemplateBuilderForm` precedent) |
| lg | 16px | Section padding, row vertical/horizontal padding (matches every existing row component) |
| xl | 24px | Layout gaps, screen-edge padding |
| 2xl | 32px | Major section breaks — e.g. the gap between the "Next in program" card and the Templates section on Workout home; between the day list and the Training Maxes section on program detail |

Exceptions: none.

## Typography

This project's existing 4-token type scale (`theme.typography`) already satisfies the "3–4 sizes, 2 weights" contract — reuse verbatim, no new sizes/weights needed for this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 (24px) — program/day row labels, form input values, progression-authoring row text, empty-state body copy |
| Label | 13px | 400 (regular) | 1.3 (~17px) — `theme.typography.caption`; secondary row captions ("3 days · Linear progression"), progression-type pill labels, set-scheme row labels |
| Heading | 20px | 700 (bold) | 1.2 (24px) — `theme.typography.title`; screen titles ("Programs", program name, "Set your training maxes"), section headings ("Training Maxes", "Program progress") |
| Display | 32px | 700 (bold) | fixed 35px (~1.09) — `theme.typography.display`. Not required by this phase's screens (no hero numeral) — available at planner/executor discretion only if the program-detail screen wants one focal number (e.g. current cycle count); not mandatory. |

## Color

Dark-first, dark-only palette (`theme.colors`, established Phase 1, no light theme in v1). 60/30/10 split for UI chrome:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0E11` (`theme.colors.background`) | Screen background across all new Programs screens and the picker/sheet overlays |
| Secondary (30%) | `#161A1F` (`theme.colors.surface`) + `#1E232A` (`theme.colors.surfaceAlt`) | `surface`: program-list rows, program-detail day-row cards, TM-setup rows, progression set-scheme nested cards (matches `TemplateBuilderForm`'s `exerciseRow` treatment). `surfaceAlt`: unselected progression-type pill, unselected day-badge background |
| Accent (10%) | `#4F8EF7` (`theme.colors.accent`) | **Reserved for, exactly:** (1) the "Next in program" card's accent border + title text (mirrors the Workout tab's `resumeCard`/`resumeTitle`); (2) "+ Add a program" primary CTA and the "Add & start" / "Build a custom program" link text; (3) the selected progression-type pill (None/Linear/%TM, `MetricToggle` reuse); (4) the "▶ Next" pointer badge on the program-detail day list; (5) all Save buttons introduced by this phase (program builder's Create/Save, TM-setup sheet's Save); (6) "Compute from 1RM" helper link text; (7) "Set as active" action text on program detail. Nothing else uses accent — day-row chevrons, static labels, and progression-icon glyphs stay `text`/`textMuted`. |
| Destructive | `#EF4444` (`theme.colors.danger`) | **Reserved for, exactly:** the "Remove program" button inside its confirmation `Alert.alert` (destructive style). Not used for deload or missed-rep feedback on the finish screen — a deload is an expected, automatic training-plan adjustment, not an error state, and uses the amber `badge` token instead (see below), never red. |
| Badge (existing, non-accent) | `#F59E0B` (`theme.colors.badge`) | Reused (not new) — same "notable event" meaning as the existing PR badge (Phase 2 finish screen). This phase extends its use to the new "Program progress" section's per-exercise event pill: weight-bump ("+2.5kg"), deload ("−10%"), and TM-bump ("TM +2.5kg") labels. A plain "hold" (missed, under deload threshold) event uses `textMuted`, not the badge — only an actual *change* (bump/deload/TM-bump) earns the amber pill. |

Accent reserved for: "+ Add a program" CTA, "Next in program" card accent chrome, "Add & start"/"Build a custom program" links, selected progression-type pill, program-detail "▶ Next" badge and "Set as active" action, all new Save buttons, "Compute from 1RM" link. Never used for static labels, day-row chevrons, or non-interactive chrome.

## Screen & Interaction Contract

Prescriptive component-level contract for this phase's five new/changed surfaces, per CONTEXT.md's locked decisions (D-01 through D-17) and RESEARCH.md's architecture (`lib/progression.ts`, `db/programs.ts`).

### 1. Workout home — "Next in program" card (`app/(tabs)/index.tsx`, MODIFIED)

Placed `theme.spacing['2xl']` below the existing resume/start-empty block, **always visible regardless of resume state** (same rule as the existing Templates section below it — starting a program day is a peer entry point to starting from a template, D-04's "tap any day" applies at the program-detail level, not gated by an in-progress session at the home level).

- **No active program:** card is omitted entirely — nothing renders in its place (no empty-state prompt at the home-screen level; discovery happens via the Settings/More → Programs row, matching the design spec's placement).
- **Active program present:** `surfaceAlt`-background card with an accent hairline border (exact `resumeCard` treatment reused), containing: "🗓️ {Program name}" (accent, Body 700, mirrors `resumeTitle`) as the tappable label, and a secondary caption (Label, `textMuted`): `"Day {position+1} of {total}: {day/template label}"` e.g. `"Day 2 of 3: Day B — Squat, Press, Deadlift"`. Tapping the whole card starts that program day: `startWorkoutFromTemplate` (D-05's origin-marker write: `workouts.program_id` + `workouts.program_day_position` set to the current pointer) → active-workout screen, exactly mirroring `handlePickTemplate`'s existing flow.

### 2. Programs manager — `app/programs/index.tsx` (NEW)

Reached via a new "Programs" row on Settings/More (D-01/D-17's settled placement), styled identically to the existing "Body Measurements" nav row (`toolRow`/`navRow`/`navChevron` reused verbatim).

- **Appbar:** back chevron `‹ More` (accent, Body 700, `backButton`/`backText` styles reused verbatim) + screen title "Programs" (Heading token).
- **Active program section** (only rendered if a program is active, D-01): heading "Active" (Label, `textMuted`), single row = the active program (same row anatomy as below, plus a small accent "Active" pill trailing before the chevron). Tap → program detail (screen 4).
- **Your programs list**: every other user-owned program (bundled-materialized or custom-built), same row anatomy as `TemplateRow`: leading 🗓️ + text column (name as primary Body line; caption as secondary Label line — `"{N} days · {origin}"` where origin is `"Linear"` / `"Percent-TM"` / `"Mixed"` depending on the days' progression types) + trailing chevron. Tap → program detail.
- **"+ Add a program" primary CTA** (accent, full-width button, mirrors `startButton`): opens the Add-a-program overlay (screen 3).
- **Empty state** (zero programs ever added): heading + body per Copywriting Contract, plus the same "+ Add a program" CTA (no separate illustration needed — matches the project's plain-text empty-state precedent).

### 3. Add-a-program overlay (NEW, full-screen overlay — mirrors the active-workout add-exercise picker's `pickerOverlay`/`pickerHeader` pattern)

Header: `‹ Cancel` (accent, dismisses) + title "Add a program".

Two sections, stacked:

- **"Bundled programs" (PROG-04):** two rows, one per bundled definition (D-14):
  - `📈 Linear 5×5 (3-Day)` — caption: "Full-body strength, 3 sessions a week. Increase weight every time you hit your reps."
  - `🌊 Percent-Based Wave (4-Day)` — caption: "One main lift per day, 4-week wave built around your training max."
  - Tapping a row opens a **read-only preview** (day-by-day list, same row anatomy as program detail's day list, non-tappable in preview) with a single bottom CTA **"Add & start"** (accent, full-width). Confirming triggers `materializeBundledProgram` (RESEARCH.md Pattern 2); if the bundle is the %TM wave, immediately chain into the TM-setup sheet (screen 5, D-16) before returning to program detail. Materializing while another program is already active triggers the **non-destructive switch-active confirmation** below.
- **"Build your own" (PROG-01/D-17):** single link/row "🗓️ Build a custom program" (accent, Label 700) → opens the program builder (below).

**Program builder (custom, inline continuation of this overlay or its own pushed screen — planner's routing choice):**
- Name field (`TextInput`, same `input` style as `TemplateBuilderForm`'s Name field), placeholder "Program name".
- Ordered "Days" list: each row is an existing template the user picked (📋 glyph + template name + `"{N} exercises"` caption, exact `TemplateRow`-derived anatomy), with the same reorder ▲/▼ + remove ✕ controls as `TemplateBuilderForm`'s exercise rows (identical `stepperGroup`/`reorderGroup` styling, 44×44 touch targets).
- "+ Add day" button (outline style, mirrors `addExerciseButton`) → opens the existing folder-grouped template picker (`TemplateRow` + `FolderSectionHeader`, the exact list already rendered on Workout home) in single-select mode; picking a template appends it as the next day. A template may be added more than once (e.g. an A/B/A alternating split) — no de-dup guard.
- **Save button** ("Create program", full-width accent, mirrors `saveButton`): disabled until name is non-blank AND at least 1 day is present (stricter than the template builder's name-only gate, since a 0-day program has nothing for "Next in program" to surface). On save: `createProgram` + `program_days` rows pointing at the picked templates in order, `program_state` initialized to position 0. If the picked days include any `percent_tm` exercises, chain into the TM-setup sheet (D-16 applies to custom-built %TM programs too, not only the bundled one).

**Switch-active confirmation** (non-destructive — `Alert.alert`, default/non-destructive button style, not red): triggered whenever adding/starting a program while a different program is already active (D-01). Title: "Switch active program?" Body: "{Current program name} will no longer be your active program. Its own progress is saved and you can switch back anytime." Buttons: **Cancel** / **Switch**.

### 4. Program detail — `app/programs/[programId].tsx` (NEW)

Reached by tapping any row on screen 2.

- **Appbar:** back chevron `‹ Programs` + screen title = program name (Heading token).
- **"Set as active" action** (accent, Label 700, top-right of appbar or directly below the title): shown only if this program is NOT the currently active one; tapping it triggers the same switch-active confirmation as above (or no confirmation if no program is currently active).
- **Day list**, `theme.spacing.xl` below the title: every `program_days` row in order, `TemplateRow`-derived anatomy (📋 + template name + `"{N} exercises · {progression summary}"` caption, e.g. `"5 exercises · Linear"` or `"4 exercises · %TM week 2"`). The row this program's `current_day_position` points at (only meaningful if this program is active) carries a small leading **"▶ Next"** badge (accent text, Label 700) before the day glyph. **Every row is tappable (D-04)** — tapping any day starts a workout from that day and moves the pointer to it, exactly like screen 1's card but reachable for any day, not only the pointed-to one. Tapping a non-active program's day still starts a workout from it but does **not** count as a program-origin workout for THIS program's advancement unless the switch-active confirmation was accepted first (mirrors D-05's ad-hoc-vs-program-origin distinction — starting a day from a program that isn't active is intentionally blocked or auto-triggers switch-active; planner's call on which, but never silently advances a non-active program's pointer).
- **"Training Maxes" section** (only rendered if any day in this program has a `percent_tm` exercise, D-10/D-16): heading "🎯 Training Maxes" + one row per distinct %TM exercise across all days (exercise name + current `training_maxes.max_kg` in display unit + trailing "Edit" text button, accent) → opens the TM-setup sheet (screen 5) pre-filled, in edit mode for that single exercise.
- **"Remove program" destructive link**, bottom of the screen (Label, `theme.colors.danger`, matches the delete-reading link precedent from Phase 5): opens the destructive confirmation below.

**Destructive confirmation — remove program:** `Alert.alert`, destructive style. Title: "Remove this program?" Body: "This deletes the program and its day list. Your logged workout history isn't affected." Buttons: **Cancel** (style: cancel) / **Remove** (style: destructive).

### 5. Training-max setup sheet — `app/programs/training-maxes.tsx` (or a modal route, NEW; D-16)

Presented as a full-screen overlay (`pickerOverlay`/`pickerHeader` pattern), triggered automatically the first time a %TM program is added/started (D-16), or manually via the "Edit" link on screen 4.

- **Header:** `‹ Cancel` (accent) + title "Set your training maxes" (first-time) / "Edit training max" (single-exercise edit mode).
- **Per-exercise TM row** (one per distinct %TM exercise in the program, first-time mode; exactly one in edit mode): exercise name (Body) + current/entered TM value (Body, right-aligned, tappable) — tapping opens `NumericKeypad` (reused verbatim) labeled `"{Exercise name} training max ({unit})"`.
- **"Compute from 1RM" helper link** (accent, Label 700) below each row: opens a second `NumericKeypad` labeled `"Enter your 1RM for {exercise name} ({unit})"`; on Done, computes `computeTrainingMaxFromOneRepMax(oneRepMaxKg)` (default 90%, `lib/progression.ts`) and pre-fills the TM field above — still directly editable/overridable before Save, never auto-saved without the user seeing the computed number first.
- **Save button**, bottom, full-width accent (mirrors `saveButton`): label "Save training maxes" (first-time, all rows must have a non-zero value before this enables) / "Save" (single-exercise edit mode). On save, writes `training_maxes.max_kg` per exercise and returns to program detail (or completes the Add-a-program flow if this was the first-time chain from screen 3).

### 6. Template builder — progression authoring (`components/TemplateBuilderForm.tsx`, MODIFIED — D-17)

Extends each existing exercise row's card (the `exerciseRow` nested-surface block that already holds the target-sets/target-reps steppers) with one new sub-section, directly below the existing stepper row:

- **Progression-type selector**: `MetricToggle` reused verbatim, 3 options — "None" / "Linear" / "%TM". Default: **None** (existing behavior, unchanged for exercises that don't opt in).
- **If "Linear" selected**: reveal an inline stepper row (same `stepperGroup` visual as target-sets/reps): label `"+{N}{unit} per success"`, step size matches the display unit's plate-loadable increment (2.5kg/5lb per tap), default **2.5kg** (`DEFAULT_LINEAR_INCREMENT_KG`, RESEARCH.md), min 0. Writes `template_exercises.progression = {type:"linear", increment_kg:N}` on save.
- **If "%TM" selected**: reveal a compact nested set-scheme editor (mirrors the exercise-row card's own nesting — one level deeper, same `surface`→`surfaceAlt` card-on-card treatment used elsewhere): a small ordered list of set rows, each with a percent stepper (`"{pct}% of TM"`, step 5%, range 30–100%) + reps stepper (reuses the existing `stepperGroup` control) + an "AMRAP" toggle checkbox on the last set only (small tappable label + checkmark, 44×44 target). "+ Add set" / per-row "✕" remove, mirroring the exercise-row list's own add/remove pattern. Writes `template_exercises.progression = {type:"percent_tm", sets:[{pct,reps,amrap?}]}` on save. This is a small fixed-shape entry form (percent + reps + AMRAP-flag per set) — **not** a generic rule editor (PROG-05/v2 stays out of scope; only the two locked rule shapes are ever produced here).
- No change to the builder's existing Save button copy or enablement logic — progression is optional metadata on top of the existing required name+exercises gate.

### 7. Finish/summary screen — "Program progress" section (`app/active-workout/summary.tsx`, MODIFIED — D-02)

Added between the existing stats-row (Duration/Volume/PRs) and the PR list, **only rendered when the just-finished workout has a program origin** (`workout.programId !== null`, Pitfall 1/7's guard — an ad-hoc or template-only finish shows nothing new here, zero layout change for the common case).

- Heading: "Program progress" (Heading token).
- One row per exercise that carries a progression rule on this day, same row anatomy as the existing PR row (`surface` card, `prRow` styling reused): exercise name (Body) + outcome text (Body, `text`) + a trailing amber `badge` pill (reused PR-badge styling) **only when something changed**:
  - Linear success: `"{exercise} — hit all sets."` + badge `"+{N}{unit}"` (next weight bump).
  - Linear hold (miss, under deload threshold): `"{exercise} — missed a rep. Same weight next time ({fails}/{threshold})."` — no badge (plain `textMuted` outcome text, not amber — a hold is not a "win," per the Destructive/Badge color rule above).
  - Linear deload: `"{exercise} — {threshold} misses in a row."` + badge `"−{pct}%"`.
  - %TM (any day that isn't a cycle-completing day): `"{exercise} — prescribed {pct}% × {reps}."` — informational only, no badge (weight was prescribed, not earned).
- **Cycle-complete banner** (only on the day that wraps `current_day_position` back to 0, D-03/D-12): a distinct `surface` card above the per-exercise rows, accent-bordered like `resumeCard`: heading "🎉 Cycle complete" + one line per bumped TM: `"{exercise} training max +{N}{unit} → {newTM}{unit}"`.
- Below this new section, the pointer-advance caption: `"Next up: Day {position+1} of {total} — {day label}."` (Label, `textMuted`), always shown for a program-origin finish regardless of progression outcomes.
