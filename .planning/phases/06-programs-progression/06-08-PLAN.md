<objective>
Close the Test-3 BLOCKER (PROG-02): a linear-progression program day now PRESCRIBES the lift's current progressed working weight at day start, and that weight is keyed per-LIFT across the whole program so a Squat bump on Day A carries to Day B.

Purpose: Two compounding defects (06-UAT.md ## Gaps). (A) PRIMARY — `startWorkoutFromProgramDay` only calls `prefillPercentTmSets`; a linear exercise never gets prescribed sets, so the active-workout screen falls back to LOG-01 last-performance and shows the last-lifted weight (the +2.5 is computed and badge-shown but never prescribed). (B) SECONDARY — linear state is keyed per-template-exercise-row, so Day A Squat and Day B Squat progress independently. The approved resolution: prescribe linear sets at day start from a per-lift shared working weight, and make `applyProgressionAndAdvance` read/write that per-lift state (`program_exercise_progress`, created in Plan 06-07) instead of the per-row `template_exercises` columns. The active-workout screen already renders prescribed sets when they exist (app/active-workout/[workoutId].tsx: the `setRows.length > 0` branch), exactly as it does for %TM — so no screen change is needed; the entire fix is in the db/programs.ts data layer.
Output: `prefillLinearSets` + per-lift progression read/write in db/programs.ts, and updated + extended vitest coverage.
</objective>
