# Phase 4 — UI Design Contract

> Visual and interaction contract for the Stats & Charts phase (STAT-01..04). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** — React Native + Expo (TypeScript) project. shadcn is a web/Tailwind-only tool and does not apply. Confirmed: no `components.json`, no `tailwind.config.*`, no `postcss.config.*` anywhere in the repo. Registry safety gate: not applicable. |
| Preset | not applicable |
| Component library | none — hand-rolled RN components styled exclusively against `theme.ts` design tokens. Established precedent across Phases 1–3: `ExerciseRow`, `WorkoutRow`, `TemplateRow`, `FilterChipRow`, `SetRow`, etc. This phase follows the same convention; no new UI framework is introduced. |
| Icon library | **Emoji glyphs**, matching the shipped precedent in `constants/muscleIcons.ts` (one emoji per `MuscleGroup`) and the bare-glyph chevron (`›`) / plus (`＋`) used in `WorkoutRow`/`TemplateRow`/exercise list. Reuse the exact same 10 muscle-group emoji for chart legend swatches, record-board rows, and PR-feed rows so an exercise's muscle group reads identically everywhere in the app. `@expo/vector-icons` (already a project dependency per CLAUDE.md) is permitted only where no existing emoji/glyph fits (none identified for this phase — every icon need below is covered by existing glyphs or plain text). |
| Font | System default (no custom font family declared in `theme.ts`) for all UI text — **except** chart axis tick labels. Per RESEARCH.md Pitfall 3, victory-native XL's `axisOptions.font` requires a loaded Skia `SkFont` via `useFont(source, size)`, or axis labels silently fail to render (chart itself still draws). No `.ttf` currently exists in the repo — **planner must bundle one** (e.g. `assets/fonts/Inter-Medium.ttf`, weight matching `theme.typography.caption`'s intent). Axis label size: 12px, color `theme.colors.textMuted` (#8B94A3) to read as secondary/supporting text, never competing with the data itself. |

## Spacing Scale

This project already ships and has used a 5-token scale across three phases (`theme.spacing`) — reuse it verbatim rather than introducing the template's generic 7-token scale. All values are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/glyph gaps, tight inline padding (e.g. gap between PR-feed row's icon and label) |
| sm | 8px | Compact element spacing (chip row gaps, segmented-toggle internal padding) |
| md | 12px | Default element spacing (row internal gaps — matches `WorkoutRow`/`TemplateRow` precedent) |
| lg | 16px | Section padding, row vertical/horizontal padding (matches existing row components) |
| xl | 24px | Layout gaps, screen-edge padding |

**Exceptions for this phase:**
- **New token needed — `2xl: 32px`** for major section breaks on the Stats overview dashboard (D-01/D-02: PR feed → weekly volume chart → exercise picker are three distinct sections stacked in one scroll). `theme.spacing.xl` (24px) is the largest existing token and is already used for screen-edge padding; using it for both edge padding *and* inter-section gaps would make the three dashboard sections read as no more separated than a single card's internal padding. Planner should add `theme.spacing['2xl'] = 32` to `theme.ts` and use it exclusively for the vertical gap between the PR feed, weekly-volume, and exercise-picker sections on `app/(tabs)/stats.tsx`. No other new tokens needed.
- Chart canvas minimum height: 240px (per-exercise line chart), 220px (weekly stacked bar) — not a spacing token, but a fixed floor so Skia has enough vertical room to render legible axis labels + data at typical Android phone widths.

## Typography

This project's existing 4-token type scale (`theme.typography`) already satisfies the "3–4 sizes, 2 weights" contract — reuse verbatim, no new sizes/weights needed for this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 (24px) — PR-feed row text, record-board values, empty-state body copy |
| Label | 13px | 400 (regular) | 1.3 (~17px) — `theme.typography.caption`; used for chart axis tick labels, segmented-toggle/range-chip labels, PR-feed secondary line ("3RM · 2026-07-20") |
| Heading | 20px | 700 (bold) | 1.2 (24px) — `theme.typography.title`; section headings ("Recent PRs", "Weekly Volume") and per-exercise chart screen title |
| Display | 32px | 700 (bold) | fixed 35px (already declared, ~1.09) — `theme.typography.display`. Reserved primarily for the rest-timer countdown (Phase 2). **Discretionary reuse this phase:** may be used for a single "hero" numeral if the record board wants one large call-out value (e.g. current best e1RM at the top of an exercise's record board). Not required — planner/executor discretion; if unused, the record board reads fine with Heading-only sizing. |

## Color

Dark-first, dark-only palette (`theme.colors`, established Phase 1, no light theme in v1). 60/30/10 split for UI chrome:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0E11` (`theme.colors.background`) | Screen background across all new Stats screens |
| Secondary (30%) | `#161A1F` (`theme.colors.surface`) + `#1E232A` (`theme.colors.surfaceAlt`) | `surface`: PR-feed row cards, chart container card, record-board row cards. `surfaceAlt`: unselected segmented-toggle pill / unselected range chip background (nested-on-surface elements) |
| Accent (10%) | `#4F8EF7` (`theme.colors.accent`) | **Reserved for, exactly:** (1) the selected segmented-toggle pill (est-1RM / top set / volume, D-05); (2) the selected range chip (3M / 1Y / All, D-06); (3) the primary trend-line stroke on the per-exercise chart; (4) "View progress" and "See all" link text (the only navigational CTAs this read-only phase has). Nothing else on these screens uses accent. |
| Destructive | `#EF4444` (`theme.colors.danger`) | **Not used anywhere in this phase.** Stats & Charts is 100% read-only (STAT-01..04) — there are no destructive actions, confirmations, or delete flows here. Reserved for other phases' delete/discard UI only. |

Accent reserved for: selected metric-toggle pill, selected range chip, per-exercise chart trend line, "View progress" / "See all" link text. Never used for static labels, chart axis text, or non-interactive chrome.

### Chart categorical palette (weekly volume stacked bar, D-14/STAT-02)

The 60/30/10 chrome rule governs UI surfaces, not data-visualization categorical color — a stacked bar with 10 muscle-group segments necessarily needs 10 distinguishable hues. These are declared as their own fixed palette, deliberately distinct from the reserved chrome colors above (`accent` #4F8EF7, `danger` #EF4444, `badge` #F59E0B are not reused here, to keep chrome meaning unambiguous):

| Muscle Group | Hex | Order in stack/legend |
|---|---|---|
| Chest | `#5B8DEF` | 1st |
| Back | `#34D399` | 2nd |
| Shoulders | `#FBBF24` | 3rd |
| Biceps | `#A78BFA` | 4th |
| Triceps | `#F472B6` | 5th |
| Quads | `#FB923C` | 6th |
| Hamstrings | `#2DD4BF` | 7th |
| Glutes | `#818CF8` | 8th |
| Core | `#E879F9` | 9th |
| Other | `#6B7280` (muted grey) | **10th, always last** |

Per RESEARCH.md Pitfall 5: `Other` is a 37/517-exercise catch-all bucket, not a real anatomical group — it must always render last in both the stack order and the legend, using the muted grey above (not a saturated hue), so it visually reads as "miscellaneous" rather than a peer muscle group. This ordering and coloring is not optional; it is the fix for a named pitfall.

## Screen & Interaction Contract

Prescriptive component-level contract for the phase's four new/changed surfaces, per CONTEXT.md's locked decisions (D-01 through D-18).

### 1. Stats overview dashboard — `app/(tabs)/stats.tsx` (replaces "Coming soon" placeholder)

Single scrolling screen, three sections stacked with `theme.spacing['2xl']` (32px) gaps between them (D-01/D-02, no sub-tabs):

**Section A — Recent PR feed (top, D-01/D-09/D-10):**
- Heading: "Recent PRs" (`theme.typography.title`)
- List of up to **12** PR events (D-10's N), newest first, across all exercises. Each row: muscle-group emoji + exercise name (Body, `theme.colors.text`) as primary line; secondary line (Label, `theme.colors.textMuted`) shows the record kind and date, e.g. "5RM · 82.5kg · Jul 20" or "Est. 1RM · 112kg · Jul 18".
- Row surface: `theme.colors.surface` card, same padding/border precedent as `WorkoutRow` (`theme.spacing.lg` vertical/horizontal, hairline `theme.colors.border` bottom).
- Row tap → navigates to that exercise's record board (`app/stats/[exerciseId].tsx`, records view).
- Trailing "See all" link (accent, Label weight) below the capped list → `app/stats/records.tsx` (full chronological PR history).
- **Empty state** (no PRs ever logged): see Copywriting Contract.

**Section B — Weekly volume by muscle group (middle, D-01/D-14/D-15):**
- Heading: "Weekly Volume" (Heading token)
- `CartesianChart` + `StackedBar`, one bar per ISO week (Monday–Sunday, D-15), most recent ~12 weeks visible, older weeks reachable via horizontal scroll/expand.
- Segments colored per the Chart Categorical Palette above, `Other` always last/muted.
- Legend below the chart: emoji + label per muscle group, same order as the stack (Other last).
- Y-axis: tonnage in the user's display unit (D-16 — convert at render time via `lib/weightUnits.ts`, never before).
- **Empty state** (no finished workouts in window): see Copywriting Contract.

**Section C — Exercise picker (bottom, D-01/D-03a):**
- Heading: "View Progress" (Heading token)
- Reuses the existing exercise-library row/search pattern (`ExerciseRow` + search input, same as `app/(tabs)/exercises/index.tsx`) scoped to exercises with at least one logged set — tapping a row navigates to `app/stats/[exerciseId].tsx`.

### 2. Per-exercise progress chart — `app/stats/[exerciseId].tsx`

Reachable from two entry points (D-03): Section C above, and a **"View progress"** link (accent, Label weight, placed near the top of the exercise detail/edit screen `app/(tabs)/exercises/[id].tsx`, below the exercise name).

- Screen title: exercise name (Heading token).
- **Segmented toggle** (D-05), directly below the title: 3-way single-select — "Est. 1RM" / "Top Set" / "Volume". Visual style matches `FilterChipRow`'s existing pill anatomy (selected = accent fill + `theme.colors.background` text at 700 weight; unselected = `surfaceAlt` fill + `border` outline + `theme.colors.text`) — but this is a **single-select radio group**, not `FilterChipRow`'s multi-select toggle, so it needs its own small component (e.g. `MetricToggle`) rather than reusing `FilterChipRow` directly. Default selection on open: **Est. 1RM** (D-04).
- **Range chips** (D-06), below the segmented toggle: "3M" / "1Y" / "All", same single-select pill styling as above. Default: **All**. Client-side filter over an all-time fetch (RESEARCH.md Open Question 2 recommendation) — no re-query per chip tap.
- Chart: `CartesianChart` + `Line`, min height 240px, accent-colored stroke (3px width per RESEARCH.md Pattern 2 example), one point per workout (D-07). Axis labels per the Design System font requirement above.
- Pinch/pan zoom: not required for v1 (D-06) — omit unless trivially available from victory-native XL defaults; do not spend implementation effort on custom gesture code for this.
- **Empty/sparse-data states:**
  - Zero logged sets for this exercise ever: full empty state (see Copywriting Contract).
  - Exactly one data point: render the single point (no connecting line possible) plus a caption below the chart: "Log one more workout to see a trend line." (Label token, `textMuted`).
- Below the chart: a link to this exercise's full record board (reuses the same screen/route as a PR-feed row tap, i.e. this screen and the record board are two views/tabs of `app/stats/[exerciseId].tsx` — planner decides exact routing, e.g. a segmented sub-view or a second "Records" link).

### 3. Per-exercise record board (D-08/D-09)

Reachable by tapping an exercise from the PR feed, or a link from the per-exercise chart screen above.

- Heading: "Records" (Heading token).
- **Rep-max rows:** curated canonical rep counts **[1, 3, 5, 8, 10, 12]** (RESEARCH.md Open Question 1 recommendation — StrengthLog-style, matches the CONTEXT.md "Specific Ideas" reference feel). Omit a row entirely if that rep count has never been logged for this exercise (do not show a placeholder "—" row for untouched rep counts — keeps the board honest and uncluttered). Each row: "{N}RM" label (Body) + weight value in display unit (Body, `theme.colors.text`) + date achieved (Label, `textMuted`).
- **Best e1RM row:** always shown separately, above or below the rep-max rows (planner's call), using the same row anatomy. May use the `Display` type token as a single hero numeral for this one value if the planner wants a visual focal point (discretionary per Typography section above) — otherwise Body-sized like the other rows is equally valid.
- **Empty state** (exercise has zero non-warmup sets logged): see Copywriting Contract.

### 4. Full PR history — `app/stats/records.tsx` ("see all", D-10)

- Heading: "All PRs" (Heading token).
- Same row anatomy as the overview's Section A feed, but unbounded (full chronological history, newest first), rendered in a scrollable list (`FlatList`, not a capped array).
- No separate empty state needed beyond Section A's (if there are zero PRs, this screen is unreachable in practice since "See all" only appears once the feed has content — but implement the same empty copy defensively).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **None.** Stats & Charts is a 100% read-only surface (STAT-01..04) — there is no primary action button. The closest analogs are navigational links, which use the exact labels below (not a CTA verb+noun in the button sense): "View progress", "See all". |
| Empty state — PR feed (Section A, no PRs ever) | Heading: **"No PRs yet"** · Body: **"Log a working set and your first personal record will show up here."** |
| Empty state — Weekly volume (Section B, no finished workouts in the visible window) | Heading: **"No training logged yet"** · Body: **"Finish a workout and your weekly volume will appear here."** |
| Empty state — Per-exercise chart (zero logged sets for this exercise) | Heading: **"No data yet for {exercise name}"** · Body: **"Log a working set for this exercise to start tracking progress."** |
| Empty state — Record board (zero non-warmup sets for this exercise) | Heading: **"No records yet"** · Body: **"Your rep-max records will appear here once you log a set."** |
| Sparse-data caption — Per-exercise chart (exactly 1 point) | **"Log one more workout to see a trend line."** (caption below chart, not a full empty state) |
| Error state | **"Something went wrong loading your stats."** · **"Try again, or restart the app if this keeps happening."** — Deliberately does not mention network/connectivity: this app is 100% local SQLite (no server calls), so any Stats-load error is a local read/compute failure, not a connectivity issue. Offer a retry action (re-run the query), not a "check your connection" prompt. |
| Destructive confirmation | **None.** Zero destructive actions exist in this phase — no delete, discard, or reset controls on any Stats screen. |

Copy voice matches the established project precedent exactly (see `app/(tabs)/index.tsx`'s "No workout in progress" / "Start an empty workout, or repeat one from your history." and `app/(tabs)/history/index.tsx`'s "No workouts yet" / "Finish your first workout and it'll show up here."): plain sentence case, no exclamation marks, heading states the absence, body states the concrete next action.
