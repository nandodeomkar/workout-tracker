## Phase Goal (user story)

**As a** lifter training in the gym, **I want to** log every set of my workout in a couple of taps and have it saved the instant I tap ✓, **so that** logging is fast, works offline, and never loses data even if the app crashes or my phone restarts.

> This plan completes the mid-session control the loop needs (LOG-04: reorder/replace/remove exercises) and adds the two Settings rows the app depends on (global unit + default rest). It also performs the one human legitimacy checkpoint for the two [SUS] native packages (react-native-gesture-handler, expo-notifications) so the rest timer (Plan 06) can install-and-go.

<objective>
Add the Settings rows (Units + Default rest, D-14/D-07) that persist to the `settings` table, and complete LOG-04 exercise management — long-press drag-reorder and an overflow menu for Replace/Remove — wired to the Plan 03 mutations with the FLAG-1 replace guard and the UI-SPEC confirm-only-when-data-at-risk rule. Install `react-native-gesture-handler` (drag) and `expo-notifications` (needed by Plan 06) behind a mandatory package-legitimacy checkpoint.

Purpose: LOG-04 makes the active workout editable in-session; the Settings rows supply the unit and default-rest values the log screen and rest timer read. Consolidating the two [SUS] installs behind one checkpoint here (wave 3) unblocks Plan 06 (wave 4) without a second human interruption.
Output: rewritten `app/(tabs)/settings.tsx`, an interactive drag+overflow `ExerciseCard`, active-workout screen wiring for replace/remove, and the two installed packages.
</objective>
