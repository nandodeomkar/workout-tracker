## Phase Goal (user story)

**As a** lifter training in the gym, **I want to** log every set of my workout in a couple of taps and have it saved the instant I tap ✓, **so that** logging is fast, works offline, and never loses data even if the app crashes or my phone restarts.

> This plan adds the rest timer (LOG-03) that auto-starts on ✓ and fires a reliable notification with the screen off, the per-exercise rest override (D-08), and the finish/discard flow with a summary (LOG-05). After this plan a full workout can be logged, rested through, and finished with a duration/volume/PRs recap.

<objective>
Deliver the rest timer and the session-ending flow: the `expo-notifications` scheduling wrapper (`lib/restTimer.ts`, unit-tested with the notifications module mocked), the sticky bottom `RestTimerBar` with a drift-free absolute-timestamp countdown and skip/±15s (D-09), auto-start on ✓ using the per-exercise override or global default (D-07/D-08), the per-exercise rest-override pill persisted to `exercises.rest_seconds` (D-08), and the Finish/summary + Discard flow (LOG-05/D-10/D-11). Adds the one new theme token `typography.display`.

Purpose: LOG-03's "notification fires reliably with screen off" is the trust-critical gym feature; the finish summary (duration/volume/PRs) closes the loop. Both reuse the tested Plan 01 calculators and Plan 03 finish/discard/prior-bests queries.
Output: `theme.ts` (display token), `lib/restTimer.ts` + test, `components/RestTimerBar.tsx`, `app/active-workout/summary.tsx`, active-workout screen wiring, and a small `exercises.rest_seconds` setter in `db/workouts.ts`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → OS notification scheduler | Rest notifications are scheduled with the OS (AlarmManager via expo-notifications); delivery reliability depends on Android permission/Doze state. |
| rest-override input → exercises.rest_seconds | Untrusted numeric rest seconds crosses into a DB write. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-14 | Denial of Service (missed alert) | rest notification on Android 13/14 | accept | Channel-before-permission ordering (Pitfall 5) and the non-blocking "Notifications are off" banner (Pitfall 6) handle denial gracefully; exact-alarm reliability is verified by the mandatory screen-off device test, not assumed. Logging never depends on the notification. |
| T-02-15 | Tampering | `setExerciseRestOverride` numeric input | mitigate | Validate/bound the rest-seconds value (reject negative/NaN, cap) before the parameterized update. |
| T-02-16 | Repudiation / data loss | Discard from summary/app-bar | mitigate | Discard is confirmed with the exact "can't be undone" copy and cancels any outstanding rest notification so no stale alert fires for a discarded session. |
</threat_model>
