# Phase 2 — UI Design Contract

> Visual and interaction contract for Core Logging (Active Workout). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is Phase 2 of a shipped app.** Phase 1 already locked the design system (theme.ts, D-14) and established component/interaction patterns (ExerciseRow, FilterChipRow, MuscleGroupPills, in-screen app-bar, Alert.alert confirm, ToastAndroid). This contract **reuses and extends** those patterns — it does not invent a new visual language. Every "Value" below traces to either an existing token/component or an explicit CONTEXT.md decision (D-01..D-16).

| Property | Value |
|----------|-------|
| Tool | none — React Native + Expo (no web/shadcn stack; not applicable to this codebase) |

## Spacing Scale

**Deviation from GSD default template scale — this project's scale is locked in `theme.ts` (Phase 1, D-14) and has only 5 steps, not 7.** Do not introduce 32/48/64 — compose larger gaps from `xl` (e.g., two stacked `xl` gaps) rather than adding new tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, tight inline padding, badge padding |
| sm | 8px | Compact element spacing, chip/pill gaps, row internal gaps |
| md | 12px | Default element spacing, input padding, card internal padding |
| lg | 16px | Section/card padding, app-bar horizontal padding, row padding |
| xl | 24px | Layout-level gaps, empty-state top margin, screen edge padding on wide sections |

**Exception (component sizing, not a spacing token):** All primary interactive controls in the active-workout screen — the ✓ log-set button, ± steppers, rest-timer skip/±15s buttons, and numeric-keypad keys — use a **44×44px minimum touch target** regardless of their visual glyph size. This is a one-handed-gym-use requirement (LOG-01/LOG-02), sized via `minWidth`/`minHeight` on the pressable, not via the spacing scale.

## Typography

**Exactly 4 sizes (adds one to Phase 1's 3), exactly 2 weights — matches the contract limit.** The 4th size (`display`) is a **new token to add to `theme.ts`** before this phase builds the rest-timer countdown (no existing token is legible enough at arm's length mid-set). This is the only planned addition to the locked Phase 1 token file.

| Role | Size | Weight | Line Height | Source |
|------|------|--------|-------------|--------|
| Display (NEW — add `theme.typography.display`) | 32px | 700 | 1.1 (35px) | New token — rest-timer countdown digits only. Nowhere else. |
| Heading (`theme.typography.title`) | 20px | 700 | 1.2 (24px) | Existing Phase 1 token — screen titles, exercise names in active-workout cards, workout-detail header |
| Body (`theme.typography.body`) | 16px | 400 | 1.5 (24px) | Existing Phase 1 token — set-row numbers, button labels, list-row primary text |
| Label (`theme.typography.caption`) | 13px | 400 | 1.3 (17px) | Existing Phase 1 token — secondary/meta text, badges, section headers, timestamps |

Weight 700 is used only for: headings, CTA button labels, badges, and the display countdown. Everything else is 400. No third weight anywhere.

## Color

**60/30/10 split is Phase 1's established `theme.ts` palette — reused verbatim, not re-decided.** Phase 2 adds zero new colors.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0E11` (`theme.colors.background`) | Screen backgrounds: Workout tab, active-workout screen, History tab, Finish/summary screen |
| Secondary (30%) | `#161A1F` (`theme.colors.surface`) + `#1E232A` (`theme.colors.surfaceAlt`) | `surface`: exercise cards, set-row background, workout-list rows, calendar-day cells, app-bar/header bands. `surfaceAlt`: text inputs, numeric-keypad key background, inactive pills/chips, unselected segmented-control option |
| Accent (10%) | `#4F8EF7` (`theme.colors.accent`) | See explicit reserved-for list below |
| Destructive | `#EF4444` (`theme.colors.danger`) | Discard-workout button/border, Remove-exercise confirm button, delete-set icon (if surfaced), archive button border (existing pattern, unchanged) |
| Highlight/Badge (established Phase 1 secondary semantic) | `#F59E0B` (`theme.colors.badge`) | CUSTOM exercise tag (existing, unchanged); **new use in Phase 2:** "PR" badge in the Finish/summary screen and workout-detail view; warmup-set tag pill |

**Accent reserved for (explicit list — continues the exact Phase 1 usage pattern, does not expand it):**
- Primary CTA buttons: "Start empty workout", "Finish workout", "Save changes", "Resume workout"
- The ✓ log-set button when filled/completed state
- Active tab bar icon (existing, unchanged)
- Selected state on pills/chips/segmented-control (List/Calendar toggle, muscle-group picker reused for exercise-add/replace)
- Rest-timer progress ring/bar fill and the countdown digits themselves
- Text-link affordances: back-chevron header links ("‹ Workout"), "＋ Add exercise", "Edit" (workout detail → reopen logging screen), empty-state action links
- Today/selected-day marker dot on the history calendar

Do not use accent for anything not on this list (e.g., do not tint card borders, do not tint the warmup toggle, do not tint the drag handle).

## Screen & Component Contracts

### 1. Active workout screen (full-screen over tabs, D-15)

**Primary visual focal point:** the **✓ log-set button** on each set row (the highest-frequency action — every set logged is one ✓ tap). Secondary anchor: the **rest-timer countdown** (Display 32px/700, accent) while a rest is active. Everything else (steppers, names, metadata) is deliberately quieter so the eye lands on ✓ mid-set.

**Presentation:** New route outside the `(tabs)` group (sibling to `(tabs)` in the root `Stack`, same pattern as `app/_layout.tsx`'s existing `<Stack.Screen name="(tabs)" />`), `headerShown: false`, custom in-screen app-bar — mirrors the exact `exercises/[id].tsx` app-bar anatomy (back-affordance left, badge/status right) but the left control is **"Discard"** (danger-outlined text button), not a back-chevron, because leaving via system back must not silently abandon the session.

**App-bar (top, `paddingTop: insets.top + spacing.lg`):**
- Left: "Discard" (danger, triggers confirm dialog above)
- Center/below: workout name or "Workout" + elapsed-time readout (caption, textMuted, ticking mm:ss)
- Right: "Finish workout" (accent filled, `radius.md`)

**Exercise card** (`surface` background, `radius.lg`, `padding.lg`, `gap.md` between cards):
- Header row: drag-handle icon (leading, `≡`, textMuted, 44×44 touch target, long-press to reorder — no new dependency; implement via `react-native-gesture-handler`+`reanimated`, both already in the stack) · exercise name (`title`/heading style) + muscle glyph · trailing rest-override pill ("⏱ 90s ›", caption style, tap opens an inline ± stepper defaulting to the global setting) · overflow control ("⋯") exposing **Replace** and **Remove**
- Set rows, one per set, `body` sized numbers, each row `surfaceAlt` background, `radius.md`, min-height 56px:
  - Leading: set index or a **"W"** warmup chip (badge color when active, tap toggles warmup on/off — no confirm, D-03)
  - Weight control: `-` stepper (44×44) / tappable number (opens numeric keypad) / `+` stepper (44×44), step = 2.5 kg (or unit-equivalent lb step per D-14's converter), unit suffix shown (`kg`/`lb`) from the global setting
  - Reps control: identical `-`/number/`+` pattern, step = 1 rep
  - Trailing: **✓** button, 44×44, outline style pre-completion → accent-filled with a checkmark glyph post-completion (D-01). Tapping ✓ on a not-yet-touched row logs immediately using the pre-filled last-time values; tapping ✓ again (already completed) is a no-op tap-target for now (undo is out of scope this phase)
  - Ghost "add set" row below the last set: `+ Add set`, textMuted, dashed border (reuses `border` token), tap adds a new pre-filled-from-last-set row
- "＋ Add exercise" ghost button at the bottom of the exercise-card list (same visual language as the Phase 1 exercises-tab "+" add button, but full-width ghost row instead of circular icon button, to sit naturally at the end of a scrollable card list) — opens the exercise picker

**Exercise picker (add/replace):** Reuses the Phase 1 exercise-library screen wholesale — `MuscleGroupPills` + search input + A–Z `ExerciseRow` list, presented as a pushed screen or sheet over the active workout. Selecting a row adds it (Add flow) or swaps it in-place at the same position (Replace flow, preserves any already-logged sets on that slot per planner discretion — flag below).

**Rest timer** (persistent, appears the instant a set is logged, D-07/D-09): A sticky bar pinned to the **bottom** of the active-workout screen, above the tab-bar-equivalent safe area (this screen has no tab bar since it's full-screen), `surface` background, `radius.lg` top corners only, `padding.lg`:
- Center: countdown in the new **Display** typography token (32px/700), accent color
- Left: "-15s" (44×44 touch target, textMuted)
- Right: "+15s" (44×44 touch target, textMuted) and "Skip" (body, accent, ends the rest early)
- Progress indicated by a thin accent-fill bar along the top edge of this sticky bar (drains left→right as time elapses) — purely decorative reinforcement, the digits are the primary read
- On completion: local notification + vibrate (expo-notifications, per D-09) fires regardless of on-screen state; the on-screen bar visually settles at 0:00 and dims (does not auto-dismiss — user dismisses or it's replaced when the next set restarts it)

**Accessibility — icon-only controls (MANDATORY):** every icon-only or glyph-only pressable declares an `accessibilityLabel` so it survives to screen readers and to any future automated on-device testing. Required minimum: ✓ button → `"Log set"`; `-`/`+` weight steppers → `"Decrease weight"` / `"Increase weight"`; `-`/`+` reps steppers → `"Decrease reps"` / `"Increase reps"`; rest-timer → `"Subtract 15 seconds"` / `"Add 15 seconds"` / `"Skip rest"`; drag-handle `≡` → `"Reorder exercise"`; warmup chip → `"Toggle warmup set"`; overflow `⋯` → `"Exercise options"`. All controls also keep `accessibilityRole="button"` (Phase 1 convention).

### 2. Start-workout entry (Workout tab — replaces "Coming soon")

Three mutually exclusive states for this screen, selected by session state (Zustand, D-15):

- **No active session, has history:** Two stacked full-width buttons — "Start empty workout" (accent filled, primary) and "Start from history" (outlined, secondary). Below: nothing else — this is a deliberately sparse home screen (no clutter, per core value).
- **No active session, zero history ever (first use):** Same two buttons, plus the empty-state copy above rendered beneath them (small, textMuted) so first-time users aren't confused about what "from history" would even mean yet.
- **Active session already in progress (resumed):** A single "Resume workout" card (accent-bordered `surfaceAlt` card, `radius.lg`) showing the in-progress workout's start time and exercise count, tapping it re-enters the active-workout screen exactly where it left off. The two start buttons are **not shown** while a session is active — starting a second workout is out of scope.

"Start from history" opens a picker: reuses the History-tab list-row component (below) filtered to past workouts, tapping one starts a new session that copies that workout's exercise list (D-05), each exercise then pre-filling from its own most-recent performance (D-06) — not necessarily from the picked workout's numbers.

### 3. Finish / summary screen (D-10)

Full-screen, replaces the active-workout screen on "Finish workout" tap (not a modal — this is the natural end of the session, deserves full attention):
- Heading: "Workout complete" (`title`/heading)
- Three stat rows/cards (`surface` background, `radius.md`, laid out as a row of 3 on screens wide enough, stacked on narrow): **Duration** (mm:ss or h:mm), **Volume** (Σ weight×reps over non-warmup sets, unit-formatted), **PRs hit** (count)
- If PRs hit > 0: a list below the stats, one row per PR — exercise name + what was beaten (e.g. "Bench Press — new best: 82.5 kg × 5"), each row tagged with the **badge**-colored "PR" pill (reuses the CUSTOM-tag visual pattern from `ExerciseRow`)
- Single CTA at the bottom: "Done" (accent filled, full width) — returns to the Workout tab, clears the active session

### 4. History tab (replaces "Coming soon")

- Top: a two-option segmented control — "List" / "Calendar" (single-select, same visual pattern as `MuscleGroupPills`' pill row, just two pills instead of N)
- **List view:** chronological rows, most recent first, new `WorkoutRow` component mirroring `ExerciseRow`'s anatomy (leading glyph — reuse 🏋 or a calendar Ionicon — + text column with workout date/name as primary line and "N exercises · volume · duration" as the caption secondary line + trailing chevron). Reuses the exact row padding/border/touch-target values as `ExerciseRow`.
- **Calendar view:** month grid, `surface`-background day cells, `radius.sm`, days with a logged workout carry a small accent dot beneath the date number; month navigation via "‹" / "›" (Ionicon chevrons, textMuted, 44×44 touch targets) flanking a centered "Month YYYY" heading label. No external calendar package — build the grid as a plain custom component (7-column `FlatList`/`View` grid), consistent with the zero-added-dependency posture elsewhere in this stack. **(Flagged below for planner confirmation.)**
- **Workout detail:** read-only recap (same stat-row anatomy as the Finish/summary screen: duration, volume, PRs) plus a per-exercise, per-set breakdown list, and a single "Edit" CTA (accent, text-link style) that **reopens the active-workout screen in editable state** on this workout's data (D-12/D-13) — no separate lighter editor.

### 5. Minimal Settings additions (dependency of D-07/D-14, not a full Settings rebuild)

The "More" tab is still out of scope for a full build-out, but Phase 2 needs exactly two functional rows added to it (currently "Coming soon" only) because the active-workout screen depends on both:
- **Units row:** two-option segmented control, "kg" / "lb" (same pill pattern as History's List/Calendar toggle), persists to `settings`
- **Default rest row:** a labeled stepper ("Default rest: 90s", ± controls, 15s steps) persists to `settings`, used as the fallback whenever an exercise has no per-exercise override (D-08)

### 6. kg/lb display (D-14)

No per-set unit toggle anywhere. Every weight number (set rows, summary volume, PR copy, history rows) reads in whatever the global Units setting says, converted from the canonical `weight_kg` at render time by a pure `lib/` converter (vitest-tested, zero RN imports — mirrors the existing pure-logic pattern). Rounding: display to the nearest 0.5 kg or nearest whole lb (standard plate-loadable increments) — exact rounding rule is a `lib/` implementation detail, not a visual one.

## Open Flags (genuinely undecided — do not block on these, planner/executor resolve during implementation)

- **FLAG-1:** Replace-exercise mid-session — whether swapping an exercise preserves already-logged sets on that card or clears them. Visual contract above assumes "preserves the slot, sets stay attached to the position" but this is a data-model question for the planner, not a visual one.
- **FLAG-2:** Exact storage location for the per-exercise rest override (D-08 — nullable column on `exercises` vs `workout_exercises`) is explicitly called out in CONTEXT.md as a research/planner decision. The UI contract above (a rest-override pill in the exercise-card header) works identically regardless of where it's stored.
- **FLAG-3:** Numeric keypad — this contract specifies a custom in-app bottom-sheet keypad (not the OS keyboard) for weight/rep entry, sized to the 44×44 key minimum, because the OS numeric keyboard doesn't reliably support the 2.5 kg decimal increment pattern or the large-target one-handed use case. Exact key layout (3×4 grid + decimal + backspace + done) is an executor implementation detail within this constraint.
