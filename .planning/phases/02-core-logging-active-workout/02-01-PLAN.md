## Phase Goal (user story)

**As a** lifter training in the gym, **I want to** log every set of my workout in a couple of taps and have it saved the instant I tap ✓, **so that** logging is fast, works offline, and never loses data even if the app crashes or my phone restarts.

> This plan delivers the pure-math substrate the logging loop and finish summary depend on. It is the first sub-step of the crash-safe logging slice: every number the user sees (weights in kg/lb, session volume, PRs hit) flows through these vitest-proven pure functions. No RN imports, no DB — this is the testable core that later UI plans render.

<objective>
Create the four pure `lib/` calculators this phase's logging loop and finish-summary depend on: kg↔lb conversion with plate-loadable rounding (D-14/LOG-06), Epley estimated 1RM shared with Phase 4 (D-10), working-set volume excluding warmups (D-03/D-10), and PR detection (heaviest weight + best estimated 1RM vs prior history, D-10). Each ships with a colocated vitest file.

Purpose: These functions are imported by the set-entry UI (Plan 04), the finish/summary screen (Plan 06), and the History detail view (Plan 07). Building and proving them first means every downstream screen renders values from a single tested source rather than ad-hoc inline math (RESEARCH "Don't Hand-Roll").
Output: `lib/weightUnits.ts`, `lib/estimate1RM.ts`, `lib/volume.ts`, `lib/prDetection.ts` plus their `.test.ts` siblings, all green under vitest.
</objective>
