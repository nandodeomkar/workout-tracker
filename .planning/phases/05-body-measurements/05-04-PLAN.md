<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| entry-form keypad → db write | multiple untrusted numeric values + a chosen date cross into persisted rows in one transaction |
| date picker → db write | back-dated date string must be a valid, non-future YYYY-MM-DD |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Tampering | entry values (insertReadingsForDate/updateReading) | medium | mitigate | Each value converted to canonical then guarded by assertValidMeasurementValue in db/measurements.ts before write; blank rows skipped, not written as 0 |
| T-05-02 | Tampering | back-dated measured_at | low | mitigate | MonthCalendar restricts to past-or-today; assertValidMeasuredAt rejects malformed/future dates at the db layer (D-09) |
| T-05-05 | Tampering (data integrity) | same-date session re-entry | low | mitigate | insertReadingsForDate upserts per (metric,date) inside one synchronous transaction; edit/delete correct mistakes |
| T-05-SC | Tampering (supply chain) | npm install surface | low | accept | No packages installed this phase |

No `high`-severity threats — nothing blocks per `security_block_on: high`.
</threat_model>
