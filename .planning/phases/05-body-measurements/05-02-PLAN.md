**As a** lifter, **I want to** log my body weight and body-part measurements with a date and see each metric's trend over time, **so that** I can track my physical progress alongside my training — free, offline, in one place.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI form/keypad → db/measurements.ts write | untrusted numeric value + date string + custom label cross into a persisted DB row |
| bundled seed data → metric_definitions | trusted first-launch seed; must never overwrite a user-edited/custom row |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Tampering | insertReading/updateReading/upsertReadingForDate value param | medium | mitigate | assertValidMeasurementValue: Number.isFinite + non-negative + per-unitType cap before any parameterized write (ASVS V5, mirrors assertValidWeightKg) |
| T-05-02 | Tampering | measured_at param | low | mitigate | assertValidMeasuredAt: `YYYY-MM-DD` regex + reject future dates (D-09) before write |
| T-05-03 | Tampering / resource exhaustion | createCustomMetric label | low | mitigate | trim + MAX_LABEL_LENGTH (200) cap before insert (mirrors assertValidName) |
| T-05-04 | Tampering | metric/date/label reaching SQL | medium | mitigate | Drizzle parameterized query builder only — no `sql\`\`` interpolation; verified by grep gate |
| T-05-05 | Tampering (data integrity) | same-date duplicate readings | low | mitigate | upsertReadingForDate collapses same (metric,date) writes; latest-id-wins reducer (Plan 01) + edit/delete (D-09) prevent trend poisoning |
| T-05-SC | Tampering (supply chain) | npm install surface | low | accept | No packages installed this phase (RESEARCH audit N/A) |

No `high`-severity threats (local-only, single-user, no auth/network) — nothing blocks per `security_block_on: high`.
