## Spacing Scale

This project already ships and has used a 6-token scale across four phases (`theme.spacing`) — reuse it verbatim. All values are multiples of 4. No new tokens or exceptions needed for this phase.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/glyph gaps, tight inline padding, text-column internal gap (matches `TemplateRow`/`WorkoutRow`) |
| sm | 8px | Compact element spacing (range-chip gaps, section internal gaps) |
| md | 12px | Default element spacing (row internal gaps, keypad grid gaps) |
| lg | 16px | Section padding, row vertical/horizontal padding (matches every existing row component) |
| xl | 24px | Layout gaps, screen-edge padding |
| 2xl | 32px | Major section breaks — e.g. the gap between the quick-weigh-in card and the metric list on the Measurements index screen |

Exceptions: none. Chart canvas minimum height: 240px (matches Phase 4's per-exercise chart floor exactly — same Skia rendering constraints).

Dark-first, dark-only palette (`theme.colors`, established Phase 1, no light theme in v1). 60/30/10 split for UI chrome:

| Role | Value | Usage |
|------|-------|-------|

| Secondary (30%) | `#161A1F` (`theme.colors.surface`) + `#1E232A` (`theme.colors.surfaceAlt`) | `surface`: quick-weigh-in card, latest-value hero card, chart container card, history-row cards. `surfaceAlt`: unselected range-chip background, unselected unit pill (cm/in), keypad key backgrounds (all nested-on-surface elements) |
| Accent (10%) | `#4F8EF7` (`theme.colors.accent`) | **Reserved for, exactly:** (1) the "Log measurements" primary CTA button; (2) the "Quick weigh-in" card's accent border/title text (mirrors the existing `resumeCard`/`resumeTitle` treatment on the Workout tab); (3) the selected range chip (3M/1Y/All); (4) the selected cm/in unit pill on Settings; (5) the trend-line stroke + point markers on the per-metric chart; (6) "+ Add custom metric" and "+ Add a reading" link text; (7) the Save button on the add/edit form. Nothing else uses accent — metric row icons, chevrons, and static labels stay `text`/`textMuted`. |
| Destructive | `#EF4444` (`theme.colors.danger`) | **Reserved for, exactly:** the "Delete" button inside the delete-reading confirmation alert (D-09). Not used anywhere else in this phase — editing a reading is non-destructive and uses accent, not red. |

Accent reserved for: "Log measurements" CTA, quick-weigh-in card accent, selected range chip, selected cm/in pill, chart trend line, "+ Add custom metric" / "+ Add a reading" links, form Save button. Never used for static labels, chart axis text, or non-interactive chrome.

## Screen & Interaction Contract

Prescriptive component-level contract for this phase's three new screens plus the Settings additions, per CONTEXT.md's locked decisions (D-01 through D-12).

### 1. Measurements index — `app/measurements/index.tsx` (NEW)

Reached via the "Body Measurements" row on the Settings/More tab (D-10). Single scrolling screen.

- **Appbar:** back chevron `‹ More` (accent, Body weight 700, mirrors `app/stats/[exerciseId].tsx`'s `backButton`/`backText` styles exactly) + screen title "Body Measurements" (Heading token) below it.
- **Quick weigh-in card (D-08a), `theme.spacing['2xl']` below the title:** `surface`-background card with an accent hairline border (mirrors the Workout tab's `resumeCard`), containing: "⚖️ Quick weigh-in" (accent, Body 700) as the tappable label, and a secondary caption showing state — `"Logged today: {value}{unit}"` if today's weight is already recorded, or `"Log today's weight"` if not. Tapping the whole card opens `NumericKeypad` (reused verbatim, `allowDecimal: true`) labeled `"Body weight ({unit})"`, pre-filled with today's already-logged value or the most recent prior weight if none logged today. On Done: **upsert** — if a `weight` reading already exists for today's date, update its value; otherwise insert a new dated row. This keeps "logged today" a simple, unambiguous state per D-09's correction-control intent.
- **"Log measurements" primary CTA**, directly below the quick-weigh-in card: full-width accent button (mirrors `startButton`/`startButtonText` from `app/(tabs)/index.tsx`), label "Log measurements". Opens screen 3 (Add/Edit Measurements form) in **dated-session mode** — all metrics shown, date defaults to today.
- **Metric list**, `theme.spacing['2xl']` below the CTA, grouped into the two sections from the Metric Icon Registry ("Body Weight" then "Body Measurements"), each section preceded by a small section label (Label token, `textMuted`, matches `FolderSectionHeader`'s treatment). Each row (`MetricRow`, new component, same anatomy as `TemplateRow`): leading emoji (20px, 26px-wide column) + text column (label as primary line, Body/`text`; latest-value caption as secondary line, Label/`textMuted` — `"{value}{unit} · {relative date}"` e.g. `"82.5kg · Today"` / `"38cm · 3 days ago"`, or `"No data yet"` if never logged) + trailing chevron `›`. Tap row → `app/measurements/[metric].tsx`.
- **"+ Add custom metric" link** (accent, Label 700) at the bottom of the list (D-02) → opens a small inline form: free-text label input + a 3-way unit-type picker (weight / length / percent, reuse `MetricToggle` — exactly 3 options, appropriate per Pitfall 1) + Save, which inserts a new `metric_definitions` row with `is_custom: true`.
- **No empty state needed at this screen level** — the 15 built-ins are always seeded, so the list is never empty; "no data yet" is expressed per-row, not as a full-screen empty state.

### 2. Per-metric detail — `app/measurements/[metric].tsx` (NEW, mirrors `app/stats/[exerciseId].tsx` per RESEARCH.md Pattern 4)

Reached by tapping a metric row on screen 1.

- **Appbar:** back chevron `‹ Body Measurements` (same style as above) + screen title = metric label (Heading token).
- **Latest-value hero card** directly below the title: `surface`-background card (mirrors `recordHeroCard`), containing the latest value at the Display token size + unit (accent color, matches `recordHeroValue`), with a date caption below (Label, `textMuted`, e.g. "Jul 20, 2026"). If no readings exist yet, this card is omitted entirely (folds into the empty state below).
- **Range chips** (3M / 1Y / All) — `MetricToggle` reused verbatim, default selection **All** (D-11).
- **Chart:** `CartesianChart` + `Line` (accent stroke, 3px width) + `Scatter` (accent, radius 6) for single-point visibility — identical component usage to `app/stats/[exerciseId].tsx:194-201`, min height 240px, axis font per Design System above. Data source: `buildMeasurementSeries` (not `buildChartSeries` — per RESEARCH.md Pitfall 3, no min/max reduction) + unit conversion via `kgToDisplay` (weight) / `cmToDisplay` (length, new) / pass-through (percent).
- **Empty state** (zero readings ever for this metric): heading + body copy per Copywriting Contract, plus a "+ Add a reading" link (accent) that opens screen 3 in **single-metric mode**, pre-scoped to this metric + today.
- **Sparse-data caption** (exactly 1 point): same treatment as Phase 4 — caption below the chart, Body/`text`, centered (see Copywriting Contract).
- **History list**, below the chart, `theme.spacing.xl` gap: reverse-chronological list of every dated reading for this metric. Each `HistoryRow` (new component): date (Body, `text`) as primary text + value (Body, `text`, right-aligned) as a second column, with two trailing 44×44 icon buttons — edit `✎` (opens screen 3 in edit mode, pre-filled) and delete `🗑` (opens the Alert.alert destructive confirmation, D-09). **Both icon-only buttons are labelled for screen readers: `accessibilityRole="button"` + `accessibilityLabel="Edit reading"` / `"Delete reading"`** (icon-only actions carry no visible text, so the label is mandatory — apply the same treatment to any other icon-only glyph button introduced by this phase). Row anatomy/padding matches the existing `recordRow` pattern (`theme.spacing.lg` vertical/horizontal padding, hairline border-bottom).
- **"+ Add a reading" link** (accent, Label 700) below the history list — same target as the empty-state link above, always visible even once data exists (so back-dating an older reading doesn't require deleting/re-adding).

### 3. Add/Edit Measurements form — `app/measurements/entry.tsx` (or a modal route, NEW; shared by both entry models per D-08)

Presented as a full-screen overlay (mirrors the active-workout add-exercise picker's `pickerOverlay`/`pickerHeader` pattern — `Cancel ‹` + title, `theme.colors.background` full-bleed).

- **Header:** `‹ Cancel` (accent, dismisses without saving) + title — "Log measurements" (dated-session mode, new) / "{Metric label}" (single-metric mode, new) / "Edit reading" (edit mode, either mode).
- **Date row**, top of the form: shows the selected date (defaults to today, Body/`text`), tappable to open `MonthCalendar` (reused verbatim, zero new dependency per the codebase's existing "no external calendar package" convention) as a date-picker overlay. Only past-or-today dates selectable (D-09 back-datable, never future).
- **Metric input rows:**
  - **Dated-session mode:** every built-in + custom metric renders as a row (same two-section grouping as screen 1's list), each showing the metric's emoji + label + a value field defaulting to a blank/placeholder `"—"`. Tapping a row's value opens `NumericKeypad` (reused verbatim, label `"{Metric label} ({unit})"`) to enter that metric's value; leaving a row untouched means it is **skipped on save** (D-08 — no row written for blank fields).
  - **Single-metric mode:** only the target metric's row renders, auto-opens the keypad on screen entry to minimize taps.
  - **Edit mode:** only the metric being edited renders, pre-filled with its existing value.
- **Save button**, bottom of the form: full-width accent button (mirrors `startButton`), label "Save measurements" (dated-session), "Save reading" (single-metric add), or "Save changes" (edit mode).
- **Delete reading link** (edit mode only): Label-weight destructive-red text link below Save, "Delete reading" → triggers the Alert.alert confirmation below; on confirm, dismisses the form and returns to the per-metric detail screen.
- **Input validation** (V5, not user-visible unless triggered): value must be a finite positive number within a sane range per unit type (mirrors `db/workouts.ts`'s `assertValidWeightKg`-style guards); out-of-range entries are clamped or rejected before the write — silent clamping preferred over a blocking error dialog, consistent with this app's "logging must never be gated" ethos elsewhere in the codebase.

### 4. Settings tab additions — `app/(tabs)/settings.tsx` (MODIFIED)

Two new rows added to the existing screen, using its already-established `section` pattern — no new screen-level layout needed.

- **"Body Measurements" navigational row** (D-10): new `section` block containing a single tappable row styled exactly like the existing `toolRow`/`toolRowText` (Tools section rows), trailing chevron `›` added, label "Body Measurements" → `router.push('/measurements')`.
- **"Length units" row** (D-04): new `section` block, structured identically to the existing "Units" (kg/lb) section — label "Length units" (caption, `textMuted`) above a two-pill row using the exact existing `pill`/`pillActive`/`pillIdle`/`pillLabel*` styles, options "cm" / "in". Independent setting key (`length_units`), never derived from or synced to the existing `units` (kg/lb) key (D-04 — mixed preferences like lb + cm are explicitly supported).
