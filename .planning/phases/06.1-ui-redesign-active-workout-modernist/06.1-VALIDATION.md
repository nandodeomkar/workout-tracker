# Phase 06.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Derived from `06.1-RESEARCH.md` § Validation Architecture. This is a UI re-skin
> over the existing logging engine — most surface has no automated render tests
> (none installed, per CLAUDE.md "What NOT to Use"). Automated coverage targets the
> **new pure-logic helpers** the redesign introduces; screen behavior is verified by
> the UI-SPEC § Regression Guard manual checklist, matching how Phase 2/3/6 were verified.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest 4.1.10, Node environment, `better-sqlite3` in-memory for DB-layer tests |
| **Config file** | `vitest.config.ts` (repo root) — `include: ['**/*.test.ts']`, `watch: false` |
| **Quick run command** | `npx vitest run <specific-file>.test.ts` |
| **Full suite command** | `npx vitest run --no-file-parallelism` |
| **Estimated runtime** | quick <5s per file; full suite runs single-file (no parallelism) |

> **Windows note (user memory):** the full suite MUST use `--no-file-parallelism` on
> this machine — parallel workers trigger a `better-sqlite3` paging-file crash. Never
> add `--watch`.

---

## Sampling Rate

- **After every task commit:** Run `npx vitest run <touched-file>.test.ts` for any new/modified `lib/*.ts` pure-logic file.
- **After every plan wave:** Run `npx vitest run --no-file-parallelism` (full suite).
- **Before `/gsd-verify-work`:** Full suite green **AND** the UI-SPEC § Regression Guard checklist walked manually on-device.
- **Max feedback latency:** <5 seconds (quick), full suite bounded by single-file execution.
