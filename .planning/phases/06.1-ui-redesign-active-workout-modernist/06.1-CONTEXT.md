<domain>
## Phase Boundary

Rebuild **one screen** — `app/active-workout/[workoutId].tsx` — to the Modernist
look, and add an **Instrument / Focus** mode toggle. Also do a **global
`theme.ts` token rewrite** (dark Modernist rendition) that the rest of the app
inherits automatically.

**In scope:**
- `theme.ts` — replace token *values* (keep the existing key shape so every other
  screen keeps compiling) with the dark Modernist palette + Archivo typography +
  radius 0. Load the Archivo font.
- `app/active-workout/[workoutId].tsx` — structural rebuild to the prototype:
  - **Instrument mode** (default): session-volume strip; dense per-exercise cards
    with a sparkline + e1RM delta, a `Set / Kg / Reps / ✓` grid, warm-up "W" rows,
    current-row accent rail, PR flash star, Add set, Add exercise.
  - **Focus mode**: exercise-progress segments + set-progress segments; giant
    Weight/Reps readouts with −/+ steppers; "Last · …" line; big Log button;
    horizontal exercise rail.
  - Header (Discard / title-with-chevron + elapsed / Finish), mode toggle tabs.
  - Redesigned **rest gauge** (tick-marked track, −15 / +15 / Skip) and **idle**
    rest state.
  - Redesigned **numeric keypad** sheet (label + big value, step −/+ row, 3-col
    keypad with ⌫, Done bar).
  - Redesigned **exercise menu** sheet (Add warm-up set / Remove exercise) and
    **add-exercise** full sheet (search + candidate list).
  - Themed **discard dialog** (replacing the OS `Alert`).
- The supporting sheet components it mounts (`RestTimerBar`, `NumericKeypad`,
  `PlateCalculatorSheet`, `OneRMCalculatorSheet`, `WarmupSuggestionSheet`,
  and the add-exercise picker) restyled to Modernist. The three calculator
  sheets keep their behavior; only their chrome changes.

**Out of scope (parallel redesign track / later):**
- The prototype's **Home screen** and **bottom tab bar** — Home is being
  redesigned in parallel; the real active-workout screen is a pushed route and
  renders no tab bar.
- Every other screen's *structure* (History, Stats, Exercises, Templates,
  Programs, Measurements, Settings). They inherit the new `theme.ts` tokens
  automatically but are NOT restructured here.
- Data-model / migration changes. This phase adds **no** new tables or columns.
- The finish **summary** screen (`app/active-workout/summary.tsx`) restructure —
  see OQ-1 for how Finish reconciles with the prototype's in-screen summary.

<decisions>
## Locked Decisions (from user Q&A 2026-07-24 + handoff)

- **D-01 Scope:** Active-workout screen only (structural). Confirmed.
- **D-02 Theme strategy:** Rewrite the **global** `theme.ts` now to the dark
  Modernist tokens. Keep the existing token *keys* (`colors.background`,
  `surface`, `surfaceAlt`, `text`, `textMuted`, `accent`, `border`, `danger`,
  `badge`; `spacing.*`; `typography.*`; `radius.*`) so no other screen breaks —
  change only the values, and *extend* typography (font family, weights,
  letter-spacing, an uppercase label/kicker role, big display sizes).
- **D-03 Depth:** Full — build BOTH Instrument and Focus modes plus the
  volume strip, sparkline/e1RM delta, PR flash, and the redesigned rest gauge +
  keypad. No reskin-only shortcut.
- **D-04 Dark rendition, not the light system:** The Modernist `styles.css`
  ships a **light** ground (`#f3f2f2`). The user chose the **dark** prototype
  look. `theme.ts` implements the dark rendition below; the light `styles.css`
  is a token/where-red-goes reference only. App stays dark-only (existing D-14).

### Typography (Archivo)
- Font family **Archivo**, weights **400 / 600 / 800** — load via
  `@expo-google-fonts/archivo` + `expo-font` `useFonts` (gate render on load, or
  `SplashScreen`). Thread `fontFamily` into every typography token.
- Roles seen in the prototype (px / weight / treatment):
  - `display` giant numbers (Focus weight/reps, keypad value): **46 / 40 px, 800, tabular-nums**.
  - `heading` screen titles: **30px, 800, letter-spacing -0.02em**; exercise name **18px, 800**.
  - `title` sheet titles / list items: **15px, 700/800**.
  - `label`/kicker: **9.5–10px, 600, letter-spacing .1em, UPPERCASE** (`#7d7979`/`#9b9797`).
  - `body`: **11–13px, 400** (muted meta), **13–15px, 700** (values).
  - Set-grid numbers: **19px, 800, tabular-nums**.
- Existing `theme.typography` (title/body/caption/display) must be extended, not
  just revalued — add `label`, weights, `letterSpacing`, and a way to apply
  uppercase. Keep old keys resolvable so untouched screens keep rendering.

### Icons
- Prototype uses **Lucide** line icons (inline SVG). Add **`lucide-react-native`**
  (peer: `react-native-svg`, already present via victory/skia stack — verify) OR
  map each to the closest `@expo/vector-icons` Feather glyph. **Prefer
  `lucide-react-native`** for 1:1 fidelity (check-, plus, chevron-right,
  chevron-down, more-vertical, more-horizontal, flame, trash, star, timer,
  rotate-ccw, x, minus). Planner decides; note the added dependency.

### Mode behavior (new presentation, existing engine)
- **D-05 Instrument = the current screen, re-skinned.** Checkmark-to-log,
  keypad edit, ± steppers, Add set, Add/Replace/Remove exercise, drag-reorder,
  rest timer — all map 1:1 to existing handlers (see Reuse Map). New visual-only
  bits: the volume strip, the per-exercise sparkline + e1RM delta, the current-
  row left accent rail, the PR flash star.
- **D-06 Focus = new single-set view over the same rows.** Shows the first
  pending set of the focused exercise: giant weight/reps with ± steppers (tap
  value → keypad), "Last · <prev perf>" line, one big **Log** button, a
  set-progress segment bar, an exercise-progress segment bar, and a horizontal
  exercise rail to switch focus. Logging a set advances to the next pending set;
  when an exercise completes, focus auto-advances to the next exercise with
  pending sets (mirror the prototype's `focusLog`). Mode choice is ephemeral UI
  state (Zustand session store or local state) — **not** persisted to SQLite.
- **D-07 Rest gauge** keeps `RestTimerBar`'s absolute-timestamp logic; only the
  visual (tick track + fill + moving indicator, −15/+15/Skip, and an idle "log a
  set to start" state) changes.
- **D-08 Themed discard dialog** replaces the OS `Alert` for Discard with an
  in-screen sheet matching the prototype (exact copy preserved: "Discard this
  workout?" / "All sets logged in this session will be deleted. This can't be
  undone."). Remove/Replace confirmations: planner decides whether to also
  convert to themed sheets or keep `Alert` (see OQ-2).

### Copywriting (preserve existing, adopt prototype casing)
- Primary CTAs: **LOG SET** / **ADD SET** / **ADD EXERCISE** / **SAVE WORKOUT**
  / **DISCARD** / **FINISH** — uppercase per Modernist.
- Rest idle: "Rest timer idle · log a set to start".
- Keep every existing error toast string verbatim (they're behavior, not chrome).

## New data the prototype shows — where it comes from (Phase-4 stats already computes these)
- **Per-exercise sparkline + e1RM delta:** reuse Phase-4 helpers
  (`loadExerciseChartSets` / `buildChartSeries` / `estimate1RM`) to get the last N
  e1RM points per exercise and the delta vs the previous session. Needs a small
  read query; **no** new table. (OQ-3: how many points, and delta baseline.)
- **PR flash:** reuse Phase-4 PR detection (`detectPRs` /
  `computeExerciseRecordBoard`) — a set is a PR when its e1RM beats the all-time
  best e1RM before this session. The prototype's inline `prevBest`/`e1rm`
  comparison is a stand-in for this. (OQ-4.)
- **Session-volume strip:** cumulative Σ(weight×reps) of logged working sets.
  The prototype hard-codes a `goal = 3000` for the fill %. **We have no per-
  workout volume goal.** (OQ-5: drop the goal/fill semantics and show cumulative
  volume with fixed reference ticks, or derive a goal.)

- **OQ-1 Finish summary:** The prototype renders a rich finish summary
  (Duration/Volume/Sets/Records grid + new-records list + Save/Back) **as an
  in-screen overlay** on the active screen, then Save/Discard. The app currently
  does `finishWorkout` → `router.replace('/active-workout/summary')` (a separate
  screen). Decide: (a) keep the existing navigation and leave `summary.tsx`
  restyle to the parallel track (minimal here — Finish still navigates), or
  (b) implement the prototype's in-screen finish overlay here. **Recommend (a)**
  to stay inside the one-screen scope; revisit if the user wants the overlay.
- **OQ-2 Confirmations:** Convert Remove/Replace `Alert`s to themed sheets too,
  or only Discard? (Prototype only shows a themed sheet for Discard + the
  exercise menu.)
- **OQ-3 Sparkline window:** number of e1RM points + the delta baseline
  (last session vs rolling average). Also: what to show for an exercise with no
  history (prototype draws a flat line, delta "—").
- **OQ-4 PR baseline:** confirm all-time best e1RM (excluding the live session)
  as the PR threshold, matching Phase-4 records.
- **OQ-5 Volume-strip goal:** no goal exists — pick the cumulative-with-ticks
  treatment or define a goal source.
- **OQ-6 Vendor the handoff:** copy the prototype HTML + `styles.css` + `readme`
  into `docs/design/active-workout/` so the source of truth survives the temp
  dir and is reviewable in-repo.
- **OQ-7 Title-tap "minimize":** prototype taps the header title (chevron) to

- **OQ-8 Regression guard:** every Phase-2/3/6 behavior (crash-safe writes, rest
