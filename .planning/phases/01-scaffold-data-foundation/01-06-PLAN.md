  <name>Task 1: On-device offline foundation smoke test</name>
  <read_first>
    - .planning/phases/01-scaffold-data-foundation/SKELETON.md — the "Capability Proven End-to-End" and the documented run command
    - .planning/phases/01-scaffold-data-foundation/01-RESEARCH.md — Pitfall 1 (Expo Go incompatible — must use dev client), Environment Availability (device/EAS fallback)
    - CLAUDE.md — expo-dev-client mandatory; EAS free-tier build limits if no local Android SDK
  </read_first>
  <what-built>
    A complete offline foundation: Expo SDK 57 dev-client app; 13-table SQLite schema via Drizzle migrations 0001 (full schema) + 0002 (additive indexes); silent first-launch seed of ~400–500 curated exercises; a 5-tab shell; a searchable/filterable Exercises library; and custom-exercise create/edit-in-place/archive. Every DB-layer behavior is already covered by the automated vitest suite (`npx vitest run` green): schema-applies, seed populate/idempotency/no-clobber, migration upgrade data-safety, filter logic, and CRUD.
  </what-built>
  <how-to-verify>
    1. Build/run the dev client on a real Android device: `npx expo run:android` (or an EAS development build if no local Android SDK — see CLAUDE.md free-tier notes). Confirm you are NOT using Expo Go (it cannot load expo-sqlite).
    2. Put the device in AIRPLANE MODE (WiFi + mobile data OFF) before first launch.
    3. Cold-launch the app. Expect: no crash, no network error, no onboarding/unit-picker/seed-progress screen — it lands directly on the tabs (D-16).
    4. Open the Exercises tab. Expect a flat A–Z list of ~400–500 exercises, each showing "muscle group · equipment". Type a few letters — the list live-filters by name (case-insensitive substring). Select muscle-group and equipment chips — confirm OR-within-row / AND-across-rows filtering and one-tap clear (D-07).
    5. Create a custom exercise (name + muscle group + equipment + optional notes). Try a name that already exists — confirm the non-blocking "already exists — open it?" warning still lets you proceed (D-12). Confirm the new exercise appears in the A–Z list with a "custom" badge.
    6. Open a SEEDED exercise, rename/re-tag it, save — confirm the edit persists (D-10). Archive it — confirm it leaves the default list; toggle "Show archived" — confirm it reappears and can be unarchived (D-11). Confirm there is no delete option.
    7. Force-kill the app and relaunch (still offline). Confirm your custom exercise and your edit to the seeded exercise both persist, and the library is not re-seeded/duplicated (crash-safe local persistence, FNDN-01).
    8. Confirm throughout that no functionality required a network connection.
  </how-to-verify>

  </verify>
